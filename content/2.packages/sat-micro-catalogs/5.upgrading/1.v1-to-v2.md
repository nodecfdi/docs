La versión `2.0.0` rediseña la forma en que se distribuyen y consultan los catálogos: pasa de exponer archivos `.json` crudos con `wrapCatalog()` a **módulos TypeScript/ESM generados, búsquedas `O(1)` con `Map`, soporte de vigencias, límite elevado a 250 filas y bundles IIFE para navegador**.

## Resumen de cambios incompatibles (*breaking changes*)

- **Node.js mínimo**: sube de `^18 || ^20 || ^22` a `^22.13.0 || ^24 || ^26`.
- **Subpath `./raw/*.json` eliminado**: los catálogos ya no se importan como JSON crudo ni requieren `with { type: 'json' }`. Ahora se importan como módulos ESM tipados desde cada dominio (`/cfdi-40`, `/nomina`, etc.) o desde `/catalogs/<slug>`.
- **`wrapCatalog()` eliminado**: reemplazado por catálogos ya instanciados y por `createCatalog()` para catálogos personalizados.
- **`SatCatalog` ya no hereda de `Array`**: ahora implementa `Iterable<T>` con un `Map` interno *lazy* (`O(1)`) y no duplica los objetos en memoria para añadir `etiqueta`.
- **Métodos renombrados**: `findAndReturnEtiqueta()` → `label()` y `findAndReturnTexto()` → `text()`.

## Tabla de equivalencias

| v1.0.2 | v2.0.0 |
| --- | --- |
| `import raw from '@nodecfdi/sat-micro-catalogs/raw/cfdi_40_usos_cfdi.json'` | `import { cfdi40UsosCfdi } from '@nodecfdi/sat-micro-catalogs/cfdi-40'` |
| `const catalog = wrapCatalog(raw)` | Ya viene instanciado (o usa `createCatalog(items)` para datos propios) |
| `catalog.findAndReturnEtiqueta('G01')` | `cfdi40UsosCfdi.label('G01')` |
| `catalog.findAndReturnTexto('G01')` | `cfdi40UsosCfdi.text('G01')` |
| `catalog[0]` | `cfdi40UsosCfdi.all()[0]` o `cfdi40UsosCfdi.items[0]` |
| `catalog[0].etiqueta` | `cfdi40UsosCfdi.label(item.id)` o `cfdi40UsosCfdi.options()[0].label` |
| `catalog.length` | `cfdi40UsosCfdi.size` |
| `catalog.find((r) => r.id === 'G01')` | `cfdi40UsosCfdi.get('G01')` (en `O(1)`) |

## Pasos para migrar

::steps
### Actualiza el paquete y verifica tu versión de Node.js

Asegúrate de usar Node.js `>= 22.13.0` y actualiza la dependencia a `^2.0.0`.

### Reemplaza imports de `./raw/*.json` y `wrapCatalog`

**Antes (`v1.0.2`)**:

```ts [cfdi.ts]
import { wrapCatalog } from '@nodecfdi/sat-micro-catalogs';
import usosRaw from '@nodecfdi/sat-micro-catalogs/raw/cfdi_40_usos_cfdi.json' with { type: 'json' };

const usosCfdi = wrapCatalog(usosRaw);
const etiqueta = usosCfdi.findAndReturnEtiqueta('G01');
const texto = usosCfdi.findAndReturnTexto('G01');
```

**Después (`v2.0.0`)**:

```ts [cfdi.ts]
import { cfdi40UsosCfdi } from '@nodecfdi/sat-micro-catalogs/cfdi-40';

const etiqueta = cfdi40UsosCfdi.label('G01');
const texto = cfdi40UsosCfdi.text('G01');
```

### Actualiza accesos de arreglo para `<select>`

Si en `v1` recorrías el catálogo esperando la propiedad `etiqueta` precalculada, reemplázalo por `.options()`:

**Antes (`v1.0.2`)**:

```ts [select.ts]
const options = usosCfdi.map((item) => ({
  value: item.id,
  label: item.etiqueta,
}));
```

**Después (`v2.0.0`)**:

```ts [select.ts]
const options = cfdi40UsosCfdi.options({
  activeOn: new Date(),
});
```

### Aprovecha las novedades de `v2.0.0`

- **Más catálogos incluidos (límite subido de 100 a 250 filas)**: ahora tienes `cfdi40Monedas`, `cfdi40Paises`, `ret20Paises`, `nominaBancos` y `nominaTiposDeducciones` listos para usar.
- **Esquemas no estándar soportados**: `cfdi40Estados`, `nominaEstados`, `hyp10ClavesHyp`, `cfdi40TiposFactores` y `cfdi40ReglasTasaCuota` ahora están completamente tipados y funcionan sin errores.
- **Bundles IIFE para navegador**: consulta [Bundles IIFE](/packages/sat-micro-catalogs/browser/iife-bundles) si quieres cargar los catálogos vía `<script>` sin bundler.
::
